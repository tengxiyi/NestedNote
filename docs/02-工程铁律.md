# 拾光笔记 / NestedNote —— 工程铁律

> **本文件是本项目的最高优先级文档。**
> 当本文件与任何其他文档、注释、口头约定、既有代码冲突时：**以本文件为准**（见《00-项目章程》§5.1）。
>
> 适用范围：所有 `nested` 仓库的代码、脚本、迁移、文档、CI 配置，以及所有参与者（人 或 AI Agent）。
> 违反条款的代码**不得合并、不得发版**；已合并的违反项视为**缺陷（P1）**，须限期修复。

## 0. 如何阅读本文件

### 0.1 措辞等级（RFC 2119 风格）

| 词 | 含义 | 违规后果 |
|---|---|---|
| **禁止 / 绝不**（MUST NOT） | 红线，任何理由都不行 | 直接拒绝合并 / 回滚 |
| **必须**（MUST） | 硬性要求，除非走豁免流程 | 拒绝合并 |
| **应该**（SHOULD） | 默认这么做；偏离需在 PR 说明理由 | 需 Reviewer 明确同意 |
| **可以**（MAY） | 允许的自由度 | — |

### 0.2 规则编号

```text
T  总纲铁律（十条，不可协商）
D  数据完整性
A  架构与分层
R  Rust 代码
F  Flutter / Dart 代码
Q  数据库与迁移
S  安全与隐私
P  性能与资源
E  错误处理与可观测性
U  UI / 编辑器
Z  测试与质量门禁
B  构建、依赖与发布
V  版本、分支与协作
M  文档与沟通
```

### 0.3 豁免流程（唯一的破例通道）

> **口头的、聊天里的、注释里的"这次先这样"一律无效。**

1. 写 ADR（`docs/adr/NNNN-*.md`），说明：为何必须偏离、影响面、回退方案、失效期限。
2. 至少 1 名非作者 Reviewer 批准。
3. 若偏离 **T 组或 D 组** → 必须项目负责人批准。
4. ADR 中标注 **豁免到期时间或待办任务**；到期未处理的须重新审批。
5. 豁免不得长期化：同一处第 3 次豁免 = 必须重构。

### 0.4 配套文档（本文件不重复它们的内容）

| 文档 | 记什么 | 什么时候看 |
|---|---|---|

# T 组：总纲十条铁律

> 这十条是价值观，其余条款都是它们的展开。任何"效率"上的理由都不足以违反它们。

### T1 · 数据不可丢（Data is Sacred）

**禁止**任何可能导致已提交用户数据丢失的操作与设计。性能、内存、UI 流畅度、开发速度，全都排在数据完整性之后。
**必须**保证：写操作要么完整提交，要么完全回滚；崩溃、断电、强杀进程后数据库仍可打开且已提交数据完好。

#### T1 修订说明（2026-10）：回收站保留期

**本条曾隐含"永不物理删除用户数据"。现引入一个显式例外：回收站中的内容在保留期
（默认 15 天）后被自动彻底删除。**

**为什么要有这条修订，而不是直接改代码**：不写清楚的话，就会变成
"铁律说 A、代码做 B"——这正是 §9.1 明令禁止的文档缺陷。
半年后没人能从代码里看出"当初为什么允许自动销毁数据"。

| 项 | 内容 |
|---|---|
| **改动** | 回收站内容超过保留期后自动物理删除 |
| **保留期** | `NestedCore::TRASH_RETENTION_DAYS`（单一常量，默认 15 天） |
| **触发时机** | 应用启动时执行一次（`trash_purge`） |
| **理由** | 与主流笔记应用的行为一致；回收站不能无限占用磁盘。用户明确要求 |
| **代价** | 超过保留期的内容**不可恢复**，包括误删 |
| **保持不变的部分** | ① 用户在笔记本树里的"删除"**只做软删**，不做物理删除；<br>② 回收站内的"彻底删除"需要二次确认；<br>③ 活跃数据（未删除的笔记与笔记本）**任何情况下都不会被清理触碰**；<br>④ 清理**不会级联**：笔记本下只要有未删除的笔记，就跳过不删（防止产生孤儿笔记） |

**因这条例外而必须存在的三道防线**（见 `docs/design/19` §5.4 与实现注释）：

1. **可预期**：界面显示剩余天数，让倒计时可见，而不是让内容无声消失；
2. **可调整**：保留期是一个命名常量，改一处即可调整或关闭（关闭方式是把值改得极大，
   **不要**注释掉调用点——那会让它变成死代码，下次没人知道它为什么在）；
3. **可追溯**：本修订说明 + `docs/design/19-笔记本树右键菜单规划.md` §0.0。

> 如果将来要**彻底取消**自动清理，请在本节追加一条新的修订说明，
> 而不是删除这一段——"曾经允许过什么、后来为什么收回"同样是需要留存的决策记录。

### T2 · 阶段串行，不跳步（No Skipping）

**禁止**在上一阶段未通过 Gate（见《开发计划》各阶段 Gate）时开始下一阶段编码。
**禁止**同时开发所有模块；实施顺序遵循《技术文档》§46。
**必须**：先设计文档 → 再接口 → 再实现 → 再测试。

### T3 · 本地优先（Local-First）

**必须**：先写本地存储 → 立即更新 UI → 后台再同步。
**禁止**任何"等服务器返回成功才更新本地/UI"的数据路径（认证、配额查询等非内容操作除外）。

### T4 · Rust Core 是唯一事实来源（Single Source of Truth）

**禁止** Flutter 层直接访问 SQLite、直接读写数据文件、或实现业务规则。
所有业务事实（笔记、标签、附件、搜索、迁移、同步）由 Rust Core 决定；Flutter 只负责呈现与交互。

### T5 · 文档模型优先（Document Model First）

**禁止**把 HTML/Markdown 当作核心持久化格式。
核心格式**必须**是结构化 Block Model（`Document { version, blocks[] }`），HTML/Markdown/纯文本都是**投影（renderer）**，不是真相。

### T6 · 变更可追踪（Revision First）

**禁止**"就地覆盖、无痕迹"的数据写入路径。
每一次修改**必须**产生可追踪的变更记录（revision / operation log）；CRDT 只在其确有需要且经 ADR 批准后引入。

### T7 · 删除即软删（Soft Delete Always）

**禁止**对 `notes` / `notebooks` / `attachments` / `tags` 执行物理 `DELETE`。
**必须**用 `is_deleted` + `deleted_at`（附件用墓碑 + 引用计数），物理回收只能由显式的 GC 流程在保留期之后执行，且 GC 必须先确认同步已完成。

### T8 · 文件不进数据库（Files Outside the DB）

**禁止**把图片、附件、二进制大对象写入 SQLite BLOB。
**必须**使用内容寻址存储（`SHA-256` → `attachments/ab/cd/<hash>`），数据库只存元数据与引用。

### T9 · 按需加载（Lazy Everything）

**禁止**把"看不到的内容"整块加载进内存：列表、文档、图片、搜索结果都必须按视口/分页/缩略图按需加载。
**必须**为每一种缓存设定容量上限与淘汰策略。

### T10 · 全过程可验证（Everything Verifiable）

**禁止**合并无测试的新逻辑、无验收标准的任务、无基准的性能声明。
每一处"完成"，**必须**能用一条命令或一个可观察现象证明。

# D 组：数据完整性

- **D1 必须原子写。** 一次业务操作（如"保存笔记"= 正文 + 元数据 + 标签 + revision + sync 队列）**必须**在单个数据库事务内提交；禁止多事务分步提交。
- **D2 禁止裸 `DELETE`。** 见 T7。GC 是唯一例外，且必须：可配置保留期、有日志、有干跑（dry-run）模式。
- **D3 必须原子落盘文件。** 附件与导出文件**必须**"写临时文件 → fsync → rename"；禁止直接写目标路径。
- **D4 必须校验写入结果。** 附件写完后**必须**校验 SHA-256 一致；备份**必须**在 manifest 中记录每个文件的哈希与条目计数。
- **D5 恢复必须可校验。** 恢复流程**必须**先校验 manifest，再替换数据；**禁止**未经校验直接覆盖用户数据。
- **D6 迁移必须单向且不可变。** 已发布的 migration 文件**禁止**修改（见 Q 组）；结构变更只允许新增 migration。
- **D7 ID 必须时间有序且全局唯一。** 统一使用 UUIDv7；**禁止**自增整数作为跨设备标识；**禁止**用文件名/标题作为标识。
- **D8 时间必须 UTC 毫秒整数。** 存储层统一 `INTEGER` UTC 毫秒时间戳；**禁止**存本地时间字符串；时区与格式化只在 UI 层做。
- **D9 删除必须留墓碑。** 与同步相关的删除**必须**保留墓碑记录，直到确认所有已知设备均已同步（或超过保留期）。
- **D10 必须防止静默覆盖。** 检测到同一数据分叉（并发修改）时，**禁止**静默取舍；**必须**产生可见的冲突（冲突副本或冲突标记 + 用户可解）。
- **D11 加密密钥绝不入库。** **禁止**把密钥/口令明文写入数据库、配置文件或仓库；**必须**使用平台安全存储（Windows Credential Manager / macOS & iOS Keychain / Android Keystore）。
- **D12 数据库必须启用保护性 PRAGMA。** **必须**：`journal_mode=WAL`、`foreign_keys=ON`、合理的 `busy_timeout`；禁止在 WAL 下同时用外部进程随意改写数据库文件。
- **D13 用户可见的破坏性操作必须可撤销或二次确认。** "清空回收站/永久删除/恢复备份（覆盖）"**必须**二次确认，并显示影响范围（条目数与附件体积）。

# A 组：架构与分层

- **A1 依赖方向单向。** 依赖只能：`Flutter UI → FFI → Rust API → Domain Service → Repository → SQLite`。**禁止**反向依赖、**禁止**跨层调用（如 UI 直接调 Repository）。
- **A2 禁止 Flutter 接触存储细节。** Flutter 层**禁止** import SQLite/文件路径/加密原语相关能力；**禁止**缓存"权威数据"。
- **A3 FFI 只暴露业务语义。** **禁止**暴露 `execute_sql` / `raw_query` / 表结构 / 行 ID 之类的实现细节；**必须**暴露 `create_note` `search_notes` `list_notebooks` 这类业务操作。
- **A4 FFI 边界必须是可序列化数据结构。** 跨 FFI 传递**必须**是明确版本的 DTO；**禁止**传递裸指针语义、**禁止**依赖内存布局、**禁止**传递 DB 连接/事务句柄给 Dart 长期持有。
- **A5 核心逻辑必须与平台解耦。** `nested-core` 及以下**禁止**依赖 Flutter、平台 UI 或具体窗口系统；平台差异必须收敛在 Platform Adapter 层。
- **A6 服务端不得成为单机功能的依赖。** 所有 P0 功能（写作、搜索、附件、导入导出、备份）**必须**在完全离线状态下可用。
- **A7 模块职责单一、边界清晰。** 每个 crate 只做一件事；**禁止**在 `nested-core` 里写 SQL、**禁止**在 `nested-db` 里写业务规则、**禁止**在 UI 层做数据校验的业务判定。
- **A8 新增依赖必须走准入。** 引入新 crate/pub 包**必须**说明：解决什么问题、体积与编译时间影响、许可证、维护活跃度、是否有更小的替代；**禁止**为一个函数引入一个大依赖。
- **A9 禁止"顺手"引入技术栈外的东西。** 换 ORM、换状态管理、换编辑器、引入 CRDT、引入向量库、引入新协议 —— 全部**必须**先 ADR（见 T2/T6）。
- **A10 公共接口改动必须评估影响面。** 改动已发布的 FFI 接口、HTTP API、数据库结构、文档格式时，**必须**给出兼容性结论（兼容 / 需迁移 / 破坏性）与用户数据迁移路径。

# R 组：Rust 代码规范

- **R1 禁止 `unwrap()` / `expect()` / panic 出现在非测试代码中。** 唯一例外：启动阶段可证明不可失败的初始化（如常量解析），且**必须**写明注释说明为何不可失败。
- **R2 禁止在库 crate 中用 `unsafe`。** 如确有必要（FFI 边界、性能热点），**必须**：独立模块 + `// SAFETY:` 说明 + 单元测试 + Reviewer 明确同意。
- **R3 错误必须类型化。** 库层用 `thiserror` 定义具体错误类型；`anyhow` **仅**允许出现在应用边界（CLI、服务入口）；**禁止**用 `String` 当错误类型向上传播。
- **R4 禁止吞掉错误。** **禁止** `let _ = ...` 忽略 `Result`（除非有注释说明为何可忽略）；**禁止**把错误降级为 `log::warn` 后继续假装成功。
- **R5 禁止阻塞异步运行时。** 在 async 上下文中**禁止**同步文件/数据库/网络的重操作；**必须**用 `spawn_blocking` 或专用线程池。
- **R6 必须使用参数化查询。** **禁止**字符串拼接 SQL（见 Q4）；**禁止**把用户输入直接插入 SQL 片段（包括表名、排序字段 —— 必须白名单）。
- **R7 必须遵守 clippy 门禁。** CI 中 `cargo clippy --all-targets -- -D warnings` 必须通过；**禁止**无理由 `#[allow(...)]`（必须带注释说明）。
- **R8 必须格式化。** `cargo fmt --check` 必须通过；**禁止**提交未格式化代码。
- **R9 公共 API 必须有文档注释。** `pub` 项**必须**有 `///` 文档；**必须**说明错误条件与副作用（是否写库、是否发网络请求）。
- **R10 代码必须可测试。** 禁止全局可变状态、禁止在构造函数里做 IO、禁止硬编码路径与时间；时间、随机、路径、网络**必须**可注入（trait 或参数）。
- **R11 并发必须显式声明。** 共享状态**必须**用明确的同步原语并注释不变量；**禁止**跨 FFI 共享 Rust 内部可变状态而不加锁。
- **R12 资源必须有界。** 内存缓存、通道、线程池、连接池**必须**有上限；**禁止**无界 `Vec`/`HashMap` 缓存长期存活。
- **R13 日志必须脱敏。** 见 S 组；**禁止** `dbg!` / `println!` 提交到主干（CLI 输出除外，且必须走统一输出层）。

# F 组：Flutter / Dart 代码规范

- **F1 必须通过 Rust 层读写数据。** 见 T4/A2。**禁止** Dart 侧实现"临时"数据逻辑（"先这样，以后再挪到 Rust"= 禁止）。
- **F2 必须通过静态分析门禁。** `flutter analyze` 必须 0 error / 0 warning；**禁止**用 `// ignore:` 掩盖真实问题（必须写明理由与关联 issue）。
- **F3 禁止在 `build()` 中做副作用。** **禁止**在构建期发起 IO、网络、数据库、导航、`setState`。
- **F4 Widget 必须可被销毁。** **禁止**泄漏 `StreamSubscription` / `Timer` / `AnimationController` / `FocusNode` / `TextEditingController`；**必须**在 `dispose` 中释放。
- **F5 列表必须虚拟化。** 长列表**禁止**一次性构建全部子项；大图**禁止**以原图解码进内存显示（必须先缩略图）；见 T9 与 P 组。
- **F6 状态管理必须有界。** 全局状态只允许放跨页面共享的会话级数据；业务数据**禁止**在 Dart 层做二次权威缓存。
- **F7 必须处理三态。** 每个数据驱动界面**必须**显式处理 loading / empty / error 三态；**禁止**只写成功路径。
- **F8 禁止硬编码文案与尺寸。** 用户可见文案**必须**走本地化资源（zh-CN / en）；**必须**支持深色模式与系统字号缩放（不破版）。
- **F9 禁止平台判断散落。** 平台差异**必须**收敛到 Platform Adapter；**禁止**在业务 Widget 里到处 `Platform.isWindows`。
- **F10 编辑器改动必须覆盖输入法场景。** 任何编辑器相关 PR **必须**在真实中文输入法、Emoji、粘贴、撤销/重做场景下自测，并在 PR 中写明测试平台与方式。
- **F11 必须遵守无障碍底线。** 交互控件**必须**有语义标签、键盘可达（桌面）、最小点击区域（移动 ≥ 44×44 dp）。
- **F12 Dart 代码必须格式化。** `dart format --set-exit-if-changed` 必须通过。

# Q 组：数据库与迁移

- **Q1 所有结构变更必须走 migration。** **禁止**直接修改生产/用户库的 schema（含"手工执行一句 ALTER"、"在代码里 `CREATE TABLE IF NOT EXISTS`"绕过迁移体系）。
- **Q2 已发布的 migration 不可变。** 修正错误**必须**新增 migration；**禁止**编辑历史文件（CI 校验文件哈希）。
- **Q3 启动必须按序执行。** `检查 user_version → 逐条迁移 → 校验 schema → 允许业务访问`；迁移**必须**在事务中执行，失败**必须**中止启动并给出可操作提示，**禁止**带病启动。
- **Q4 禁止拼接 SQL。** **禁止** `format!`/字符串相加构造 SQL；**必须**用参数绑定（`rusqlite` 的 `params!` / `sqlx` 的 bind）。排序字段/表名等无法绑定的部分**必须**用白名单枚举。
- **Q5 查询必须走索引且可解释。** 新增列表/搜索/统计查询**必须**附 `EXPLAIN QUERY PLAN` 结果，确认无全表扫描（除明确的小表与后台任务）。
- **Q6 必须避免 N+1。** 列表页**禁止**逐条查询关联数据；**必须**用 JOIN 或批量查询。
- **Q7 事务必须短小。** **禁止**在事务中做网络请求、图片解码、文件哈希等长耗时操作。
- **Q8 FTS5 索引必须与数据一致。** 索引更新**必须**与笔记写入在同一事务（或由可重放的触发器/队列保证最终一致），并且**必须**提供 `reindex` 命令与一致性自检。
- **Q9 必须定期维护。** 应用空闲或退出时**可以**执行增量优化（`PRAGMA optimize` / 分批 `VACUUM`），但**禁止**在启动关键路径上做全量 `VACUUM`。
- **Q10 迁移必须有测试。** 每个 migration **必须**有"从上一版本库升级到最新"的测试，并在 CI 中运行。
- **Q11 结构必须自带约束。** **必须**声明主键、外键、非空、唯一约束与默认值；**禁止**只靠应用层保证结构正确性（应用层校验是补充，不是替代）。
- **Q12 服务端 schema 与客户端 schema 独立演进。** **禁止**让客户端直接依赖服务端表结构；两者只通过 API 契约耦合。

# S 组：安全与隐私

- **S1 传输必须加密。** 所有网络通信**必须** TLS；**禁止**在发布构建中允许明文 HTTP（开发环境例外必须显式开关并断言非 Release）。
- **S2 密钥必须放平台安全存储。** 见 D11。
- **S3 敏感数据绝不进日志、绝不进崩溃报告。** 禁止项：密码、token、refresh token、密钥、完整笔记正文、附件内容、用户文件路径中的用户名部分（应打码）。日志**必须**默认脱敏。
- **S4 必须最小权限。** 只申请真正使用的系统权限（相机、相册、文件、通知）；**必须**在使用时请求并说明用途，**禁止**启动即索取全部权限。
- **S5 禁止执行不可信输入。** 导入 HTML/ENEX/Markdown 时**必须**清洗：剥离脚本、内联事件、外部跟踪资源；**禁止**在渲染中使用可执行内容。
- **S6 必须校验外部输入。** 所有来自用户、文件、网络的输入**必须**在 Rust 层做边界与类型校验（长度、数量、MIME、大小、路径）；**禁止**信任文件名与 MIME 声明（必须嗅探真实类型）。
- **S7 必须防路径穿越。** 使用用户提供的文件名/标题构造路径时**必须**规范化并限制在数据根目录内；**禁止**直接拼接。
- **S8 必须限流与限额。** 服务端**必须**有请求速率限制、请求体积上限、每用户存储配额；客户端**必须**有下载/上传超时与重试退避。
- **S9 数据出境与云功能必须明示并且可关。** AI/云同步等涉及数据离开设备的特性**必须**默认关闭或明确同意后开启，并说明数据去向；**禁止**静默上传用户内容。
- **S10 删除必须是真删除（在用户要求时）。** "彻底删除"**必须**删除数据库记录与对应附件文件；**禁止**留下可恢复副本（备份快照按保留策略说明）。
- **S11 依赖必须审计。** CI **必须**运行 `cargo audit` 与依赖漏洞检查；高危漏洞**必须**在 7 天内处理或记录豁免。
- **S12 发布构建必须关闭调试能力。** **禁止**在 Release 中包含调试菜单、测试后门、写死账号、示例密钥或 verbose 日志。

# P 组：性能与资源

- **P1 指标即契约。** 章程 §2.4 的北极星指标是回归门禁：任一指标相对基线退化 **> 10%** **必须**在同一 PR 中修复或给出书面解释并获得 Reviewer 同意。
- **P2 必须先测量再优化。** **禁止**以"感觉慢"为由重构；**必须**有 profile / benchmark 数据。**禁止**以牺牲可读性与数据安全换性能。
- **P3 内存必须有预算。** 空闲 50–100 MB、编辑态 100–200 MB、移动端 < 100 MB；新增功能**必须**给出内存影响估算。
- **P4 大对象禁止穿透 UI 层。** **禁止**把原图/大文件读成 Dart `Uint8List` 供多个 Widget 使用（见 T9）；**必须** "File → Thumbnail → ImageProvider"。
- **P5 缓存必须有上限与淘汰。** 每种缓存**必须**有容量上限、LRU/过期策略与清理入口。
- **P6 启动路径必须精简。** **禁止**在首屏前做：全量索引重建、全库统计、全量缩略图生成、网络请求（除显式登录流程）。
- **P7 主线程/UI 线程禁止重活。** 哈希、压缩、解析、导入导出、缩略图、索引**必须**在 Rust 侧或后台 isolate 执行。
- **P8 必须支持中断与取消。** 长任务（导入、同步、重索引、导出）**必须**可取消、可显示进度、可断点续做。
- **P9 帧预算必须被尊重。** 滚动与输入期间**禁止**在帧内做 IO 或重计算；桌面与移动均以 P95 帧时间 < 16.7 ms 为目标。
- **P10 性能报告必须可复现。** 基准**必须**脚本化（`just bench`），并记录硬件、数据集、版本；**禁止**只给结论不给方法。

# E 组：错误处理与可观测性

- **E1 必须结构化错误。** 内核错误**必须**是枚举类型（`DatabaseError` `NetworkError` `ValidationError` `SyncConflict` `PermissionError` `AttachmentError` `ImportError`），**禁止**把底层错误原样抛给 UI。
- **E2 禁止把技术细节暴露给用户。** UI 只显示可读信息 + 可操作建议 + 可选错误码；**禁止**显示 stack trace、SQL 语句、内部路径。
- **E3 错误必须可定位。** 用户可见错误**必须**携带可在日志中检索的错误码/请求 ID。
- **E4 日志分级必须正确。** ERROR/WARN/INFO/DEBUG/TRACE；Release 默认 INFO；**禁止**用 ERROR 记录预期内的业务失败（如校验失败）。
- **E5 必须记录关键路径。** 启动、迁移、备份、恢复、同步、导入导出**必须**有开始/结束/失败日志与耗时。
- **E6 禁止静默失败。** 任何失败**必须**至少满足其一：用户可见提示、重试与降级、日志记录。**禁止**"catch 后什么都不做"。
- **E7 用户数据相关失败必须可恢复。** 写失败**必须**保留用户输入（草稿/重试入口）；**禁止**让用户输入随错误消失。
- **E8 崩溃必须上报（本地优先）。** 崩溃信息默认**只**本地留存，用户可选择分享；**必须**脱敏（见 S3）。

# U 组：UI / 编辑器

- **U1 第一版禁止自研排版引擎。** **必须**基于成熟编辑器 + Document Model Adapter 实现；**禁止**在 v1 造排版内核。
- **U2 编辑器必须支持中文输入法。** IME 组词、候选、光标、撤销在桌面与移动均**必须**正确；**禁止**以"英文测试通过"作为完成标准。
- **U3 必须支持 Emoji 与 Unicode。** 光标移动、删除、字数统计**必须**按字素簇（grapheme cluster）处理，**禁止**按 UTF-16 code unit 粗暴切割导致乱码。
- **U4 自动保存必须满足时限。** 输入 debounce 300–1000 ms；切换笔记 / 关闭编辑器 / 应用退后台 / 退出**必须**立即保存；**禁止**存在"只有点保存才落盘"的路径。
- **U5 编辑内容不得丢失。** 任何导航、崩溃、错误都**禁止**静默丢弃未保存内容；**必须**有本地草稿兜底。
- **U6 危险操作必须可撤销或确认。** 删除、移动、合并标签、恢复备份等**必须**支持撤销或二次确认（见 D13）。
- **U7 交互必须有一致反馈。** 所有耗时 > 200 ms 的操作**必须**有进度或忙碌反馈；**禁止**界面"点了没反应"。
- **U8 必须尊重平台习惯。** 桌面用鼠标/键盘习惯（右键菜单、多选、快捷键），移动用手势与原生返回；**禁止**移动端机械复制桌面三栏。
- **U9 数据格式显示必须一致。** 同一数据在四端渲染结果**必须**一致（时间格式、排序、摘要截断规则统一由 Core 提供）。
- **U10 禁止阻塞式弹窗滥用。** **禁止**用模态弹窗承载可非阻塞的信息（保存提示、同步状态应走非阻塞反馈）。

# Z 组：测试与质量门禁

- **Z1 禁止无测试的新逻辑。** 核心 crate（`nested-core` `nested-model` `nested-db` `nested-search` `nested-attachment` `nested-import` `nested-export` `nested-sync` `nested-crypto`）行覆盖率**必须** ≥ 80%；UI 层关键交互**必须**有 Widget/集成测试。
- **Z2 测试必须覆盖边界与失败路径。** 每个数据操作**必须**至少：1 正常路径、1 边界（空/超长/重复）、1 失败路径（权限/损坏/中断）。
- **Z3 必须数据驱动测试。** 导入导出**必须**用真实世界样本（含中文、Emoji、嵌套列表、表格、图片、超长行）做往返（round-trip）测试。
- **Z4 禁止"修测试"来让构建通过。** **禁止**删除/跳过（`#[ignore]`, `skip:`）测试来绕过失败；**禁止**放宽断言以适配错误实现。跳过**必须**附 issue 与到期时间。
- **Z5 必须有崩溃与损坏测试。** 写入过程中强杀进程、断电模拟、损坏文件、磁盘满、权限拒绝 —— **必须**验证数据仍可用或可恢复。
- **Z6 必须有性能基准与数据生成器。** 1k/10k/100k/1M 笔记与 100 MB/1 GB/10 GB 附件数据集**必须**可由脚本一键生成（见《技术文档》§30）。
- **Z7 CI 必须门禁。** PR **必须**通过：格式化、lint、单元/集成测试、迁移测试、铁律自动检查；任一项失败**禁止**合并。
- **Z8 必须每月备份恢复演练。** 真实执行"备份 → 清库 → 恢复 → 逐条比对"，并记录报告。
- **Z9 禁止在生产库上做实验。** 压测、迁移试验、破坏性测试**必须**在生成的测试库/副本上进行。
- **Z10 缺陷必须回归测试化。** 每个修复的 bug（除纯文案）**必须**新增一条能复现它的测试，否则视为未修复。

# B 组：构建、依赖与发布

- **B1 工具链必须锁定。** `rust-toolchain.toml`、Flutter channel、`Cargo.lock`、`pubspec.lock` **必须**提交并在 CI 使用；**禁止**依赖"我这台机器能跑"。
- **B2 依赖升级必须受控。** 一次只升一类（如只升 Rust 依赖），升级后**必须**跑全量测试 + 基准；**禁止**顺手夹带无关升级。
- **B3 提交的 lock 文件禁止手工编辑。**
- **B4 构建必须可复现。** 同一 commit 在任何机器上**必须**产出相同功能版本；**禁止**依赖本地环境变量、未提交生成物、本地缓存。
- **B5 生成代码必须可重建。** FFI 绑定、序列化代码等**必须**由 `just bindgen` 等命令重建；**禁止**手工编辑生成文件（除带标记的补丁区）。
- **B6 发布必须可追溯。** 每个发布**必须**：git tag、版本号、变更日志、构建产物校验和；**禁止**发布无 tag 的包。
- **B7 发布前必须过验收清单。** **必须**执行对应阶段的验收清单（如桌面 14 条）并在发布说明中附结果；**禁止**以"改动很小"为由跳过。
- **B8 签名与密钥必须安全。** **禁止**把签名证书/密钥/口令提交到仓库；CI 中**必须**使用加密机密。
- **B9 必须支持回滚。** 发布**必须**保留上一版本，且**必须**说明数据兼容性（是否可回退、需要哪次 migration）。
- **B10 破坏性变更必须提供迁移与告知。** 涉及库结构或数据格式的变更**必须**自动迁移 + 用户可见说明 + 备份建议。

# V 组：版本、分支与协作

- **V1 分支模型。** `main` 永远可构建可运行；功能在 `feat/*`、修复在 `fix/*`、架构实验在 `spike/*`（spike 分支**禁止**直接合并，必须重写为正式实现）。
- **V2 禁止直接推 `main`。** 所有改动**必须**走 PR + 至少 1 名 Reviewer 批准 + CI 绿。
- **V3 提交必须小而聚焦。** 一个提交做一件事；**禁止**混合格式化、重构、功能、依赖升级（格式化单独提交）。
- **V4 提交信息必须规范。** 使用 Conventional Commits：`feat(editor): ...`、`fix(sync): ...`、`docs(db): ...`、`refactor(core): ...`；正文说明**为什么**，而非重复"改了什么"。
- **V5 禁止提交敏感信息与本地垃圾。** 密钥、token、本地数据库、附件、`.env`、IDE 配置、构建产物**必须**在 `.gitignore` 中；**必须**有提交前检查。
- **V6 禁止大文件入库。** 二进制样本 > 5 MB **禁止**进 git（用脚本生成或外部存储），附件测试数据**必须**可生成。
- **V7 Reviewer 必须实质审查。** **必须**检查：数据安全（D）、分层（A）、测试（Z）、性能（P）；**禁止**只留"LGTM"。
- **V8 技术债必须显式登记。** **禁止**用隐藏的 `TODO` 代替登记；所有临时方案**必须**在 `docs/tech-debt.md` 有条目（内容、影响、触发条件、预计偿还时间）。
- **V9 紧急修复必须补课。** 绕过 Gate 的 hotfix **必须**在 48 h 内补齐测试/文档，并在复盘中记录。
- **V10 不打破主干。** 合并后 `main` 若变红，**必须**由合并者优先修复，暂停其他合并。
- **V13 踩过的坑必须当场登记。** 每遇到一个"花时间才定位、且可能再犯"的问题，**必须**在同一轮工作内追加到 `docs/03-踩坑备忘.md`，写清**现象 / 根因 / 修法 / 如何避免**四要素。
  - **禁止**只写"遇到过某某问题"而不写根因——那种记录下次毫无用处。
  - **禁止**只记在聊天记录或提交信息里：本文件是唯一被检索的地方。
  - 若该坑**可以**被机器检查，**必须**同时落到门禁（见附 A），只写文档等于下次还会踩。
  - 理由：本项目已为同一个坑付过三次学费（PowerShell 脚本的 UTF-8 BOM，见备忘 §1.1）。

# M 组：文档与沟通

- **M1 设计先行。** 新模块/新协议/新数据格式开工前**必须**有设计文档（`docs/design/NN-*.md`）；**禁止**"边写边想"地实现架构级功能。
- **M2 架构决策必须 ADR。** 换库、换协议、改数据格式、偏离铁律 —— **必须** ADR。
- **M3 文档与代码同 PR。** 行为变更**必须**在同一 PR 更新相关文档；**禁止**"稍后补文档"。
- **M4 文档必须可执行。** 步骤类文档**必须**给出可复制命令与预期输出；**禁止**只写"配置一下环境"。
- **M5 计划必须维护。** 阶段/范围/验收标准变更**必须**同步更新《开发计划》并记入变更日志。
- **M6 术语必须统一。** 统一使用：笔记（Note）、笔记本（Notebook）、标签（Tag）、块（Block）、文档（Document）、附件（Attachment）、修订（Revision）、墓碑（Tombstone）、闸门（Gate）；**禁止**同一概念多种叫法。
- **M7 汇报必须给证据。** "已完成/已修复/已优化"**必须**附命令、日志、截图或基准数据。
- **M8 AI Agent 必须遵守同样的规则。** 使用 AI 辅助开发时：**禁止**接受未经测试与审查的生成代码；生成代码**必须**满足 R/F/Z 组全部要求；**禁止**用 AI 批量产出无设计依据的架构改动。

|---|---|---|---|

**已知的检查盲区**（诚实记录，避免产生虚假安全感）：

- R1 只识别字面量 `unwrap()`/`expect(`，不识别通过 trait 间接 panic 的调用；
- Q4 只检查 `format!`，不检查 `String` 拼接（如 `push_str` 拼 SQL）——这类写法在 Review 时拦；
- S3 是启发式匹配，不是熵检测，可能漏掉拆分拼装的凭据；
- 注释剥离不处理块注释与字符串中的 `//`（如 URL），可能造成漏报；
- **A-LAYERING 只看 import 的路径字符串**，不做符号解析：
  通过 `part` / `export` 间接暴露的路径它管不到（本项目目前未使用这两种写法）；
- **V13（踩坑登记）无法自动检查**："有没有写根因"是语义判断。
  只能靠每次 Gate 评审时翻一遍 `docs/03-踩坑备忘.md` 的最近改动。

> **已闭合的盲区**（曾经记在这里，现已自动化——保留记录以说明"写下来就会去做"）：
> Dart 侧的分层约束（A1/A2 的"UI 不得直接调 Repository"）曾长期没有自动检查，
> 理由是"Flutter 侧尚无代码"。Flutter 代码开始增长后随即补上了
> `nested-rules` 的 **A-LAYERING** 规则（含 6 个单元测试）。

## 附 C：违规处理

| 情况 | 处理 |
|---|---|
| PR 违反 T/D 组 | 拒绝合并，作者修复；已合并则视为 P1 缺陷，限期修复 |
| 违反 Z 组（无测试/改测试） | 拒绝合并，要求补测试 |
| 违反 V 组（直接推 main / 夹带依赖升级） | 回滚或拆分为独立 PR |
| 连续违反同一规则 3 次 | 触发复盘：是规则不合理（走 ADR 修改规则），还是流程缺失（补自动化门禁） |
| 规则本身不合理 | **允许修改规则，但必须走 ADR + 记录原因**；禁止"悄悄不遵守" |

## 附 D：本文件的维护

- 新增/修改条款**必须**走 ADR 并更新「变更日志」。
