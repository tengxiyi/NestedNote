# ADR 0002 —— 富文本编辑面选型（R2）

> 状态：**已采纳方向 —— 所见即所得（WYSIWYG）为硬性要求**（用户 2026-10 明确：
> "设定富文本后，所见即所得。不需要在预览和编辑之间通过按钮切换视图"，
> 并给出印象笔记的右栏工具栏截图作为体验基准）。
> 原选项 B（Markdown 标记 + 预览渲染）**否决**。本 ADR 修订为选型 A 的两个候选对比。
> 待确认：A1 / A2 二选一（见 §3，建议 A1）。

---

## 1. 体验基准（用户给定）

右侧栏笔记内容**上方有一行工具栏**：字体、字号、加粗/斜体/下划线/删除线、
高亮、行内代码、无序/有序列表、待办、对齐、缩进、表格、分隔线、附件……
编辑即渲染，无模式切换。R1 的「预览」按钮在 R2 达到 parity 后移除。

## 2. 候选对比（截至 2026-10）

| 维度 | A1 `appflowy_editor` 6.2.0 | A2 `super_editor` |
|---|---|---|
| 出处 | AppFlowy-IO（AppFlowy 产品的编辑器） | Superlist 团队 |
| 许可 | **AGPL-3.0（与本项目一致，可用）** | MIT |
| 文档模型 | Node 树 JSON（块 = type + delta），**Notion 式块** | 自有 Document（段落/标题/列表/图片/分隔线…） |
| 块覆盖 | 标题、列表、待办(todo)、引用、代码、分隔线、图片、表格 **全覆盖** | 标题/列表/引用/代码/图片/分隔线；表格较弱 |
| 工具栏 | **内置可定制工具栏**（含移动端/桌面端两套） | 需自组（有 attribution/selection 基础设施） |
| 中文 | 团队即中文背景，AppFlowy 产品面向中文用户，**IME 风险最低** | IME 有大量修复历史，但团队非中文背景 |
| Markdown 互转 | 需自写映射（或用其插件） | 有 `super_editor_markdown` 包 |
| 维护活跃 | 高（6.x 线持续迭代） | 高（Superlist 产品在用） |

## 3. 建议：A1 `appflowy_editor`

1. **块覆盖最贴近体验基准**：待办、表格、代码、分隔线、图片都是原生块，
   不需要我们造；
2. **工具栏内置可定制**——用户要的"内容上方一行按钮"正是它的形态；
3. **中文 IME 风险最低**：AppFlowy 本身就是中文用户为主的产品；
4. 许可 AGPL-3.0 与本项目一致，无合规负担。

A2 的优势（MIT + Markdown 包）在"我们要映射到自己的 Block serde"这一
前提下价值有限：无论选谁，映射层都不可省略，而 A1 的块语义更齐。

## 4. 架构：映射层（选谁都绕不开）

```
我们的 Block serde（落库字节，唯一事实）
  ↕ 双向映射（唯一映射点，core 层）
AppFlowy Editor 文档 JSON（编辑器的内存/序列化形态）
```

- **只写一份映射**（Dart core 层，A-LAYERING 位置不变）；
- 编辑器改动**只在保存时**序列化回 Block serde 走既有
  `save_note` 路径——修订、预览、导出全部沿用；
- R1 的 `DocumentView` 与文本投影保留为**迁移期兜底**，
  R2 达到 parity 后从编辑器移除预览按钮。

## 5. 模型增量（A10 允许：只加变体）

对照截图，现有 `InlineMarkKind`（Bold/Italic/Strike/Code/Link）缺：

- **Underline**（下划线）
- **Highlight**（高亮）

需要新增两个变体。注意点：老版本二进制读新文档会反序列化失败——
本项目当前单机单版本（同二进制读写），风险可控；
**未来同步协议设计时必须把"标记枚举版本"纳入兼容规则**（记入技术债）。

字体/字号选择器（截图里有）**首版不做**：块模型无此字段，
且对纯文本笔记价值低；先交付 B/I/U/S/高亮/代码 + 块级操作全套。

音频录制（截图里有）无对应模型能力，**不做**。

## 6. 实施顺序（确认选型后）

1. **Spike**：引入依赖 + 最小嵌入 + Block JSON ↔ 编辑器文档双向映射
   跑通一篇真实笔记（先不动正式编辑器）；
2. **替换编辑面**：右栏正文区换成编辑器 + 工具栏（截图布局），
   保存走既有路径；预览按钮移除；
3. **行内标记全套**：B/I/U/S/高亮/代码/链接 + 模型加变体；
4. 表格/图片编辑按框架能力逐步放开。
