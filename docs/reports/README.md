# 阶段评审与性能报告

本目录存放**证据**，而不是结论。所有报告都应能在 CI 或本地重跑复现（铁律 P10）。

## 命名约定

```text
gate-p0.md              阶段 P0 的 Gate 评审记录（晋级依据）
gate-p1.md
perf-YYYY-MM-DD.md      性能与内存报告（含硬件、数据集、版本）
crash-injection-*.md    崩溃注入测试报告（铁律 Z5）
backup-drill-*.md       备份恢复演练报告（铁律 Z8，每月一次）
```

## Gate 评审记录必须包含

1. **入口条件**：上一阶段 Gate 的结论与日期；
2. **交付物清单**：对照《开发计划》的 DoD 逐条打勾，或说明为何未达成；
3. **证据**：测试结果、基准数据、手动验收记录（谁、在什么设备上、什么版本）；
4. **未达标项**：明确列出并给出豁免理由与后续计划——**禁止**用"基本完成"含糊过去；
5. **风险复查**：风险登记册中哪些已消失、哪些已触发、是否新增风险；
6. **结论**：通过 / 有条件通过 / 不通过，以及下一阶段的第一件事。

## 性能报告必须包含

- 硬件与操作系统（CPU、内存、磁盘类型）；
- 数据集规模与生成方式（脚本命令）；
- 每个场景的 P50 / P95 / 峰值内存；
- 与上一份报告的对比（退化超过 10% 必须解释，铁律 P1）；
- 复现命令。

## 关于界面截图

**本目录不存放界面截图。** 原因见 `docs/03-踩坑备忘.md` §7.3：
本项目实测过自动化截屏在远程/虚拟化环境下**返回恒定同一帧**，
甚至截到无关的其它窗口——因此截图无法作为验收证据。

界面验收改用**可断言的输出**：
`%TEMP%\nested-ui-diagnostics.txt`（由 `lib/core/ui_diagnostics.dart` 写入），
它记录界面此刻看到的笔记本树与笔记列表，验证脚本可直接断言。
需要给人看效果时，请在本机运行 `just app-run` 并手动截图。
